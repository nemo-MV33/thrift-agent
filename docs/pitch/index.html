The problem

Small bugs can carry a big context bill.

Every turn repeats work.

A baseline lists files, reads them one by one and resends the full history for every edit and test command.

Old API habits survive.

An Express 4 wildcard can crash an Express 5 service before the first request reaches it.

THRIFT02 / 07

Agent workflow

Route once. Keep the prompt short.

01 / CONTEXT

Find the code

Rank files against the task. Put the useful files in the first coding prompt.

02 / BIFROST

Choose a model

Classify the task once, then pin the model that answers.

03 / TOOLS

Apply the edit

Run workspace tools through MCP. Ask before a write or shell command.

04 / TESTS

Stop on green

Run the tests after an edit. Trim old tool output if another step is needed.

Thrift sends step events to the dashboard. Bifrost logs supply routing, fallback and cost data.

THRIFT03 / 07

Bifrost integration

Gateway controls in each run.

Routing

Local embeddings classify the task. CEL rules route simple tasks to GPT-OSS 20B and harder tasks to GPT-OSS 120B.

Fallbacks

The configured chain starts at Groq, moves to Gemini and can finish on local Ollama.

Virtual keys

Separate keys control baseline access, daily spend and local-only inference.

MCP and cache

Thrift executes approved tool calls through Bifrost. Redis backs the gateway cache.

Cost comes from the gateway logs, including the linked fallback requests.

THRIFT04 / 07

Tavily integration

Check the installed version.

From claim to source

Thrift reads installed package versions, asks a model which API claims the fix depends on and searches Tavily for evidence.

The judge attaches a source and puts outdated or uncertain claims into the coding context.

Express 5 example
